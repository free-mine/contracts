# Основные сценарии

## Покупка

Пользователь разрешает `Gate` потратить необходимое количество Dollar token
и вызывает:

```text
buy(dollarAmount)
```

Dollar token переводятся напрямую в Fund,
а пользователю выпускаются FundToken по текущей `entryPrice`.

```text
User ── Dollar token ──► Fund
User ◄── FundToken ───── Gate
```

## Вывод

Вывод обрабатывается стадиями.

1. Пользователь вызывает `requestWithdrawal(amount)`.
Минимальная заявка — один FundToken. Указанные токены сразу перемещаются
в `Gate`; отдельный `approve` для FundToken не требуется.

2. Заявка относится к текущей стадии и может быть отменена,
пока Fund подготавливает расчёт.

3. Fund завершает стадию, устанавливая цену вывода от 90% до 100% текущей
`entryPrice`, и переводит в `Gate` Dollar token,
достаточные для всех заявок этой стадии.

4. После завершения стадии пользователь выбирает:

   * `withdraw` — FundToken из заявки сжигаются,
   пользователь получает Dollar token по зафиксированной цене;
   * `cancelWithdrawalRequest` — один FundToken сжигается,
   остальные возвращаются пользователю,
   а зарезервированные Dollar token возвращаются в Fund.

Отменить заявку можно и до завершения стадии. В этом случае результат тот же
для FundToken: один токен сжигается, остальные возвращаются пользователю.

## Sacrifice

Пользователь может вызвать:

```text
sacrifice(tokenAmount)
```

Указанное количество его FundToken безвозвратно сжигается
без получения Dollar token или другой компенсации.

Пожертвования не являются основной механикой Фонда и могут применяться
лишь в очень редких случаях. Как правило, обычный вкладчик никогда
не жертвует свои FundToken и никто не в силах его к такому склонить.
